# 三层根因与修复（2026-11-06 完成）

按"伤害大小"排序。**第 3 层才是主因**，1、2 层是放大器。

---

## 第 1 层：容器没有内存上限 → 整机被拖爆，systemd-oomd 整组杀

**症状**：内存涨到 30G+、swap 打满 90%，`systemd-oomd` 一次杀掉容器里
1.2 万个进程（`ExitCode=137` 但 `OOMKilled=false`）。

**修复**：`docker-compose.yml`

```yaml
    mem_limit: 24g
    memswap_limit: 24g      # 相等 = 容器不给 swap，避免把整机 zram 顶满
```

**验证**：

```bash
cat /sys/fs/cgroup/system.slice/docker-$(docker inspect -f '{{.Id}}' rocm_dev).scope/memory.max
# 25769803776
docker stats --no-stream rocm_dev     # MEM LIMIT 应显示 24GiB
```

> 注意：单靠这一层**会让情况变坏**。页缓存/匿名内存到顶后进入"回收→重读"抖动，
> 因为是可回收的干净页缓存，内核没有理由 OOM kill，表现成"容器不退出但整机卡死"。
> 这正是用户 11-06 反馈的现象，必须配合第 3 层一起用。

---

## 第 2 层：`/run/user/1000` 不可写 → VS Code Agent Host 无限崩溃重启

**症状**：

```
[error] ServerAgentHostManager: agent host failed to start
        listen EACCES: permission denied /run/user/1000/vscode-ipc-<uuid>.sock
[error] agent host failed to start, giving up after 5 restarts
[info]  [AgentHostChannel] Renderer requested connect to upstream   ← 立刻再试
```

**根因**：compose 原来只挂了单个 wayland socket：

```yaml
- ${XDG_RUNTIME_DIR}/${WAYLAND_DISPLAY}:${XDG_RUNTIME_DIR}/${WAYLAND_DISPLAY}:rw
```

容器内 `/run/user/1000` 由镜像自动创建为 `root:root 0755`，uid 1000 无法在其中创建
unix socket。宿主上这个目录其实是 `fiz:fiz 0700`。

**修复**：`docker-compose.yml` 改为整目录挂载

```yaml
- ${XDG_RUNTIME_DIR:-/run/user/1000}:/run/user/1000:rw
```

并把 `.env` 里的 `WAYLAND_DISPLAY=wayland-0` 改成 `wayland-1`（宿主实际 socket 名）。

**验证**：

```bash
docker exec rocm_dev bash -lc 'ls -ld /run/user/1000; touch /run/user/1000/_p && echo 可写'
# drwx------ rocmUser rocmUser   →  可写
```

## 第 3 层（主因）：Dev Containers 自动端口转发 × `network_mode: host` = 自激循环

**链路**：

```
Dev Containers 自动发现容器内监听端口 33173
        （= 容器内 VS Code server 的 stream 服务，server-main.js）
                ↓
在宿主上开 127.0.0.1:40321 → 容器:33173
                ↓
客户端每连接一次，Dev Containers 就执行
    docker exec rocm_dev <node> -e 'net.createConnection({host:"127.0.0.1",port:33173})…'
  起一个 stdio↔socket 桥
                ↓
因为 network_mode: host，容器内 127.0.0.1 就是宿主 127.0.0.1
   ⇒ 这条转发链自己能被自己再次连上，桥永不关闭
                ↓
每秒 ~135 个新桥（1159 次里只有 4 次正常结束）
                ↓
1200+ 孤儿进程 / 14G anon / 8417 tasks  → 整机卡死
```

**修复**：宿主 VS Code 用户设置 `~/.config/Code/User/settings.json`

```jsonc
"remote.autoForwardPorts": false,        // 关掉自动端口转发（关键）
"remote.restoreForwardedPorts": false,   // 重连时不恢复旧转发
"remote.autoForwardPortsSource": "hybrid",  // 保持原值即可，失效但不影响
```

**验证**（三个都要看）：

```bash
# 1) 容器内任务数应该稳定在 200~500，而不是每秒 +100
grep 'cur=' ~/Documents/project/ros2/memwatch/rocm_hog.log | tail -5

# 2) node -e 隧道进程应该是个位数且不增长
grep 'node -e' ~/Documents/project/ros2/memwatch/rocm_hog.log | tail -3

# 3) 宿主侧不再出现每秒上百条 Port forwarding
grep -c 'Port forwarding connection from' \
  ~/.config/Code/logs/*/window1/exthost/ms-vscode-remote.remote-containers/remoteContainers-*.log
```

**实测结果**（两个 VS Code 窗口同时开）：

```
23:13:38 cur=5.21G tasks=453   ← 峰值
23:14:54 cur=4.69G tasks=451   ← 平稳，不再上涨
node -e 隧道：4 个，5 次采样不变
（修复前：peak 16.98G / tasks 8417 / 隧道 1196 个）
```

> 需要转发端口时（例如 Jupyter 8888），在 VS Code 的 **PORTS 面板手动
> "Forward a Port"**，一次性且可控。

## 附带修掉的两个坑（不是根因，但会误导排查）

1. **`~/ros2/workspace.code-workspace` 是非法 JSON**（结尾多了 `},`），
   导致其中所有 `settings` 从未生效。已修正并补上 watcher/search/Pylance 排除规则
   → 见 `docs/03-排查手册.md` 的"顺手清障"。
2. **`Dockerfile.dev` 里那条 zoxide 安装层**：装到 `/home/rocmUser/.local/bin`，
   运行时被 `rocm-home` volume 完全遮蔽，白装且每次 build 都要访问
   `github.com` releases（没代理必失败）。已注释。

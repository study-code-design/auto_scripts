# 排查手册（下次复发时按这个顺序做）

前置：所有命令都在**宿主机**执行，不需要 root。容器名 `rocm_dev`。

---

## 0. 三个数字先读出来（10 秒）

```bash
CG=/sys/fs/cgroup/system.slice/docker-$(docker inspect -f '{{.Id}}' rocm_dev).scope
cat $CG/memory.max $CG/memory.swap.max      # 有没有上限
cat $CG/pids.current                         # 任务/线程数 ← 最关键的指标
cat $CG/memory.stat | head -12               # anon / file / kernel
cat $CG/memory.events                        # max= oom= oom_kill=
```

判读表：

| 现象 | 结论 |
|---|---|
| `anon` 大 + `pids.current` 上千 | **进程/线程风暴**（本项目的主症状）→ 走第 1 步 |
| `file` 大、`anon` 小 | 页缓存被扫描灌满 → 查大目录/搜索/索引，见第 4 步 |
| `oom_kill > 0` | 容器内部 OOM 生效了（有 `mem_limit` 时才会出现） |
| `memory.max = max` | 没有上限，整机有被拖死的风险 |

## 1. 谁在喷进程？（工具：`tools/rocm_hog_watch.sh`）

```bash
bash tools/rocm_hog_watch.sh 5        # 每 5 秒采样，Ctrl-C 停
tail -f $WORKSPACE/memwatch/rocm_hog.log   # tu 机器 = /home/tu/Documents/cpp_project/rl_rocm/memwatch/
```

日志三段式，看 **COUNT** 那段：

```
CUR ...   一行内存曲线（cur/peak/anon/file/kernel/tasks）
--- 线程数 top 5 ---
   THREADS 29 pid=... ppid=... rss=... <命令>
--- 同命令重复份数 top 5（附父进程）---
   COUNT 1196 x <命令>            ← 数量异常大的那一行就是元凶
            ↑ 1196 份 的父进程 pid=... <父命令>
            ↑↑ 祖父进程 pid=... <祖父命令>
```

- 某命令**成百上千份** ⇒ 找 `docker exec`/`child_process` 之类的循环
- 注意 `ppid` 指向 `containerd-shim`（容器 PID 1）⇒ **原始父进程已退出，
  是孤儿堆积**，真正拉动者要往上游找（见第 3 步）

## 2. 手工抓现场（不用工具，临时确认）

拿到可疑进程后，看它连的是哪个端口、stdin/stdout 是什么：

```bash
P=<可疑 pid>
tr '\0' ' ' < /proc/$P/cmdline; echo        # 命令行（含端口号）
ls -l /proc/$P/fd | head -8                 # 0/1 是 pipe 还是 socket
grep -E '^PPid|^Threads' /proc/$P/status
```

批量统计（一次读 /proc，不会自己拖慢机器）：

```bash
python3 - <<'PY'
import os, re
from collections import Counter
cg = f"/sys/fs/cgroup/system.slice/docker-{os.popen(chr(100)+'ocker inspect -f {{.Id}} rocm_dev').read().strip()}.scope"
cmd = lambda p: open(f"/proc/{p}/cmdline","rb").read().replace(b"\0",b" ").decode(errors="replace")
ppid = lambda p: int(open(f"/proc/{p}/stat","rb").read().rsplit(b")",1)[1].split()[1])
pids = [int(x) for x in open(f"{cg}/cgroup.procs").read().split()]
t = [p for p in pids if "net.createConnection" in cmd(p)]
ports = Counter((re.search(r"port:\s*(\d+)", cmd(p)) or [None,"?"])[1] for p in t)
print(len(t), dict(ports))
for pp, n in Counter(ppid(p) for p in t).most_common(3):
    print(n, "份的父进程", pp, cmd(pp)[:120])
PY
```

## 3. 顺着端口找到宿主侧是谁在转发

```bash
ss -ltnp | grep -E ':<端口>'          # 谁在监听（本项目是容器内 server 的 stream 服务）
ss -tn  | grep -c ':<端口>'           # 连接数，几百/上千就是异常

grep -E 'Port forwarding connection from' \
  ~/.config/Code/logs/*/window1/exthost/ms-vscode-remote.remote-containers/remoteContainers-*.log \
  | tail -5
```

如果出现 `Port forwarding connection from A > B > C in the container`
且一分钟几十上百条 ⇒ **Dev Containers 自动端口转发自激**，确认
`remote.autoForwardPorts` 是否被改回 `true`（宿主 VS Code 用户设置）。

## 4. 如果是 `file`（页缓存）在涨

```bash
grep 'cur=' $WORKSPACE/memwatch/rocm_hog.log | tail -5   # 看 file 列
# 巨型目录排查（顺序：容器 home → 工作区）
docker exec rocm_dev bash -lc 'du -sh ~/ros2/* ~/.cache/* 2>/dev/null | sort -h | tail'
```

本项目实测体量：`~/ros2` 57G（RLDog 17G / RL_project 16G）、`~/.cache/uv` 20G。
排除规则写在容器内 `~/.vscode-server/data/Machine/settings.json`
（`files.watcherExclude` / `search.exclude` / `python.analysis.exclude`）。

## 5. 保险丝（工具：`tools/rocm_guard.sh`）

```bash
bash tools/rocm_guard.sh                     # 默认 16G 触发
THRESHOLD=12 bash tools/rocm_guard.sh        # 更保守
DRY_RUN=1 THRESHOLD=2 bash tools/rocm_guard.sh   # 只取证不杀（演练用）
```

触发时它会把"内存明细 + 线程数 top + 同命令重复计数 + RSS top"写进
`rocm_guard.log`，然后 `docker kill`。**先取证再杀**，所以证据不会丢。

要常驻就装成 systemd 用户服务：

```bash
bash tools/install-units.sh                  # guard 16G + watch 20s
systemctl --user status rocm-guard rocm-watch
```

> 跑需要 >16G 内存的训练任务前：`systemctl --user stop rocm-guard`，跑完再 `start`。
